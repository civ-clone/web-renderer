# Review: transport and worker glue (origin/main 18f28b0)


## Area health

The happy path is solid. Requests are serialised per channel (#324) and covered by `tests/engine/transportRequests.ts`. `gameData` is no longer rebuilt twice (#333 is fixed in `WorkerTransport.rawChannels`). Notifications and `chooseFromList` go through the visibility filter. The save/load hand-over (IndexedDB plus a sessionStorage marker, gzip with a plain-JSON fallback) is careful and tested. The weak spot is failure handling. There is no error channel between worker and page: a worker exception is only a console line, a request that gets no reply hangs its channel for the rest of the session, a failed load leaves a blank page, and the one place worker text reaches the DOM (`notification`) uses `innerHTML` with strings taken from the save file. The rest is a few latent issues (DataQueue never recovers from a throwing value, a stale `UnknownUnit.tile`) and some dead code (Retryable, unused Store methods, the `orphanIds` parameter).

## Already tracked

- #175: saves leave out the new-game engine options (Earth, map size, `players`, world options). This is the "what state is lost" part of the load path for options.
- #68: `DataQueue.remove` is never called (only add/update are used). The UI's `removeObjectPath` splices arrays, so two indexed removes in one batch would shift indices. Latent until remove patches return.
- Known-issues doc: the `DataQueue` "chunk the data transfer" TODO (whole queue sent per flush).
- #449: splitting `DataTransferClient.ts`, where the request handlers and filters that this area depends on live.
- #339: the UI is never type-checked, so `Transport`/`Request` generic mismatches (for example `new Request('setOptions', …)` returning `any`) go unnoticed.
- #315: the `tradeRoutes` AdditionalData calls `city.yields()` for every city with routes on every city serialisation.
- #344: Renderer split / DOM update events. The notification `innerHTML` and the transport listener setup live in Renderer.ts.

## Engine

- core-save-game/hydrate.ts `assertCompatible`: error messages include strings straight from the file (plugin names, `type`). That is fine for an engine, but consumers have to treat them as text, which the renderer currently doesn't (finding 1).
- core-player-world/PlayerWorld.ts `register`: adds the `PlayerTile` before `VisibilityChanged`, which is why the renderer's Retryable fallback is dead. No bug.

## Simplifications

- `lib/playerWithoutActions.ts` and `lib/unitWithoutActions.ts` are the same stand-in builder with a different omitted list and marker class. One `withoutKeys(object, omitted)` helper would cover both.
- `WorkerTransport` and `ParentTransport` duplicate `receive`/`receiveOnce` over an `EventTarget`. A shared base taking the target and a `postMessage` function would remove the duplication. It should also remove the handler before calling it in `receiveOnce` (today a throwing handler stays registered) and drop the unfiltered `DataObject → toPlainObject()` fallback in `send`, which would silently ship a full rival graph if ever reached.
- Delete `src/js/Engine/IpcTransport.ts` (entirely commented-out Electron code).
- The docs are stale: docs/known-issues-and-rewrite-notes.md:20-26 and docs/TODO.md:148-155 still list #333/#326 as open and the `restart` channel as declared. `restart` is gone, and #333 is fixed by `rawChannels`.
- `loadSaveFromFile` parses the whole JSON (up to about 11 MB) only to check `format`/`entities`, and the worker parses it again. Checking a prefix, or sending the parsed object, would save one parse.

## Coverage gaps

- tests/engine/transportRequests.ts: a request whose reply never comes, or comes as an error reply, rejects or times out, and the next request on that channel still gets its own answer.
- tests/ui (new, e.g. `notifications.ts`): a `notification` string containing `<img onerror>` is shown as text, and no element is created.
- tests/engine (new `dataQueue.ts`): a value builder that throws once doesn't stop later `transferData` calls from delivering the other entries.
- tests/engine/load.ts plus a UI test: a save naming a missing plugin produces a load-failure message on its own channel, and the UI restores the main menu.
- tests/ui/savedGame.ts: the could-not-read alert for a non-JSON file contains the raw message with no HTML entities.
- tests/engine (DTC filter): a rival unit's serialised `tile` follows the unit after it moves.
