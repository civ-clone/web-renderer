# Review: build, release and test tooling (origin/main 18f28b0)

(`runwith.js` bundles a suite with a substitute `plugins.ts`; `empty-plugins-results.txt`; `run-*.txt`; `bullets.mjs`; `tsc-tests.txt`; `deploy-log.txt` is the log of deploy run 39506519550.)

## Area health

The release pipeline works and is well documented. The deploy workflow is short and correct: frozen pnpm install, release notes, `npm test`, build, `rsync --delete` to the Pages repo. Every suite printed PASS in the last deploy. The conformance runner is hardened against a run that ends silently (it requires its result markers). The test harness as a whole is not. Twenty-four engine suites pass on exit code alone, and they exit 0 with no output if the game never reaches the human's turn. The project has hit exactly that failure mode once already (`05-engine-plan.md`, "ended after `engine:start` with no output, no error and exit code 0"). Two generator problems are confirmed by running them:
- **Plugin import order changes the game.** The plugin list's order follows reversed `readdir` order, and a sorted list moves the conformance checksums.
- **Trailers leak into the release notes.** `toBullets` lets a trailer through after two blank lines, and a Claude session URL has already shipped to players in the release notes.

There is no service worker, web manifest or `sw.js` anywhere in the repo. The stale-service-worker problem on localhost comes from something else served at that origin, not from this app. Cache busting relies on Pages' `max-age=600` alone. The UI and the tests are not type-checked (#339 covers the UI).

## Engine

- core-rule and its consumers: rules at equal priority run in registration order, and registration order is plugin import order. Reordering imports changes the conformance checksums (turn 10 with sorted order, turn 1 with a shuffle). Which rules collide was not traced.
- 29 packages (e.g. base-city-yield-happiness, base-player-action-end-turn, base-unit-type-land, core-client, library-civilization, library-world) have `"main": "index.js"` in package.json but ship no index.js.

## Simplifications

- One shared runner, used by every `test:*` script, that bundles, runs with a timeout, requires `^PASS`, and cleans up its temp directory.
- Generate `plugins.ts` once at the start of `npm test` and drop the nine repeated `build:generate-plugins-ts` calls.
- Run `prettier:check` in `npm test`/CI. `prebuild` only runs `prettier:format`, so unformatted code never fails anything, and a local build rewrites tracked source.
- In esbuild.js, drop the unused `.build` loader. Move `watch` to `context().watch()` before any esbuild bump (esbuild 0.14.54 is installed, and `watch:` was removed in 0.17).
- Sort the translation imports in buildTranslationList.js as well. No conflicting duplicate keys today (checked 2,707 keys), but order should not depend on the filesystem.

## Coverage gaps

- tools/changelog.js: cases for `\n\n\n` before trailers, a trailer with no blank line before it, a final `Note: …` paragraph, and a lone `Closes #nn.` paragraph. Also assert that no bullet in `releases.json` starts with whitespace or matches `Co-Authored-By|Claude-Session`.
- A runner self-test: bundle one engine suite against an empty `plugins.ts` and require it to fail.
- buildPluginList: check that the output is non-empty, sorted, and the same when run from another cwd.
- tools/conformance.js: an optional `--reorder` run that bundles with the plugin list reversed. It should be identical once order independence is the goal; until then it documents the dependence.
- `tsc --noEmit -p tsconfig.tests.json` over tests/engine, tests/ui and their lib/ directories, as part of `npm test`.
