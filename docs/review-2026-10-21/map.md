# Review: map rendering (origin/main 18f28b0)


## Area health

The map is in good shape. Layers hold only the viewport, and Overview is the only world-sized canvas: at most 160×100 at one or two pixels a tile, so Large and Huge cost nothing extra at scale 2. Wrap-around maths is centralised in `lib/viewport.ts` (`repeatOffsets`, `tileRange`, `wrappedDelta`, `clampOrigin`) and is right on both axes. Note that the engine's `core-world` wraps **both** x and y (a torus). `World.get` matches it, and "y does not wrap" is only the renderer's "stop at the poles" view option, which `setWrapVertical` and `clampedCenterY` handle correctly. No caller mutates a cached image from `getPreloadedImage`, `replaceColours`, `renderUnit` or the coast cache. Layer failures are contained per tile and per layer (#32).

The weak spot is the partial-redraw contract. A layer clears only a tile's own square but draws past it: the stacked-unit copy, wide yield rows, and city labels overlapping each other. Unit-only changes never reach the map at all, because only `PlayerTile` objects queue a redraw. Two places are quadratic in the size of the change, which matters on the one patch that resends every tile (a government change) and on Large/Huge/custom maps. One wrong-data bug sits in `components/lib/cityYields.ts`: turns left ignores the sign of the yield.

## Already tracked

- #91: draw order and dirty regions for sprites that overlap their neighbours. It is written for iso/hex and assumes square tiles never overlap. The Units, Yields and CityNames findings above are the square-grid case.
- #274: turns left, the `Fortified` check, the map yield layout and terrain names are all re-derived in the UI.
- #359: `cityName` (components/lib/city.ts) looks the name up by the current owner's civilization.
- #358: unit status canvases are not redrawn on `devicePixelRatio` changes.
- #56 / #167: tile size hard-coded at 16, and colour keys "to come from theme manifest" in Cities, Overview and renderUnit.
- #351: an invisible NotificationWindow keeps the keyboard (a Window subclass).
- #339: the UI code is never type-checked.

## Engine

- `@civ-clone/core-world` `Tile.getNeighbour` and `World` wrap both axes. The renderer's `World.get` agrees. The brief's "y does not wrap" holds only with "Stop the map at the poles" on.
- `@civ-clone/base-unit-action-fortify` `Fortify.complete` (and `core-unit` delayed-action completions generally) raise no event. A client can't tell a unit became Fortified without re-reading it, which is why no tile goes out (finding 2).

## Simplifications

1. `TerrainAbstract.update`: dedupe by coordinate key in a `Set` (this also fixes finding 3).
2. Call `setPreloadContainer` once from Renderer rather than in every `Map` constructor. Each City screen render builds six layers, each of which clears the image map and rescans `#preload`.
3. `Units.drawTile` and `ActiveUnit.render` both draw the stacked copy at `-scale`. One helper that also returns the reach would serve both, and finding 1.
4. `NotificationWindow`'s own queue never engages: `hasOpenWindow()` queries `div.notificationWindow`, but windows have been `<dialog>`s since 5e59c26 (`Notifications.ts` uses `.notificationWindow` and does its own queueing). Remove the queue, or fix the selector (the windows reviewer's area).
5. Remove `Portal.visibleBounds`/`visibleRange` and the unused `Window` `position` option (findings 11 and 12).

## Coverage gaps

- tests/ui/unitStatus.ts (or a new tests/ui/layerOverhang.ts): a stack of two going to one, then `update([tile])`, leaves no drawn pixels outside what was cleared. The same for Yields with 6 icons.
- tests/ui/cityNames.ts: updating one of two cities with overlapping labels never draws a `fillText` into a region that wasn't cleared since the last draw.
- tests/ui/activeUnit.ts (Renderer-level): a patch carrying only a changed `Unit` (gaining `Fortified`) queues its tile for the Units layer.
- tests/ui/layerFailures.ts: extend to `CityNames` and `ActiveUnit`, so that one city or unit that throws still lets the rest draw and `portal.render()` run.
- A unit test for `turnsLeft` with a negative net yield (expect "Never"/0, not a positive count).
- A TerrainAbstract test: `update` of a contiguous block renders each coordinate once, with a time bound at 10k tiles.
- tests/ui/mapNavigation.ts: a GamePortal pointer test where `pointerdown` has no matching canvas `pointerup`, after which a hover `pointermove` (buttons 0) must not scroll.
